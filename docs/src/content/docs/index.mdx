import { Card, CardGrid } from '@astrojs/starlight/components';

itero (Latin: "I repeat") runs workflows on one machine. A workflow is a
few lines of JSON: what starts it, and the steps it takes. A step is an
action, a small executable file in any language, or another workflow.

```json
{ "on": [{ "event": "mail.received" }], "steps": ["#notify"] }
```

<CardGrid>
	<Card title="Small files" icon="document">
		A workspace is a folder: workflows as JSON, actions as executables,
		sources as executables. No action descriptions, no expressions.
	</Card>
	<Card title="Messages, schedules and files" icon="rocket">
		A message from an app, a source or `itero emit` starts runs, and
		reaches the runs waiting for it; a schedule or a watched file starts
		them too.
	</Card>
	<Card title="The Unix way" icon="seti:shell">
		An action reads its values as environment variables and prints JSON;
		its exit code says how it went. `curl`, `jq` and the shell do most of
		the work.
	</Card>
	<Card title="Kept up" icon="approve-check">
		Every message and answer is in a SQLite journal, and every step in a
		JSON log. A lost step runs again; a watchdog restarts the daemon,
		which starts at login.
	</Card>
</CardGrid>
