Run itero as a server in a container, then put the workspaces you make on
your Mac on it with [`itero ws apply`](/commands/workspace/). One
container runs the machine's daemon, [`itero daemon`](/commands/daemon/):
every workspace on its list, their journals and folders on one volume.

## The images

| Image | Has |
|---|---|
| `ghcr.io/aegea-dev/itero:0.41.0` (`:0.41`, `:latest`) | Debian, with curl, jq, python3, git, ImageMagick and Chromium: itero's examples run as they are |
| `ghcr.io/aegea-dev/itero:0.41.0-alpine` (`:0.41-alpine`, `:alpine`) | Alpine, with curl and jq: small, for those who add their own (`FROM` it, then `apk add`) |

Both run `itero daemon` under tini as user 10001, for amd64 and arm64.
`daemon.json` is `/etc/itero/daemon.json`, the state `/var/lib/itero/`.
There is no OS secret store in a container: secrets come from the
environment or a mounted folder ([Secrets](#secrets)).

The volume must be a block device: a Docker volume, or a disk such as
EBS or a persistent disk. Never NFS or EFS: SQLite's locks and its
write-ahead log are not reliable there.

An opened daemon does not start until a token can reach it, so make the
first one before the first start; it is printed once, on your terminal:

```sh
docker compose run --rm itero token create laptop
docker compose up -d
```

Then, from your Mac, in the workspace's folder:

```sh
itero context add home https://itero.example.com --ws shop
itero ws apply --context home
```

`listen` serves plain HTTP: put a proxy with TLS in front (Caddy,
Traefik), or give `daemon.json` a `tls` ([daemon.json](/reference/daemon-json/)).

## Kubernetes

For k3s, or any cluster: one pod, its volume from the cluster's default
storage class (k3s's local-path is a block device).

```sh
curl -fsSLO https://docs.itero.sh/container/k3s.yaml
```

<Code code={k3s} lang="yaml" title="k3s.yaml" />

Make the first token on the volume the pod will use, while the pod is
not running: apply the file, scale the StatefulSet to none, make the
token in a pod of its own on that volume, then scale it back.

```sh
kubectl apply -f k3s.yaml
kubectl -n itero scale statefulset itero --replicas=0
kubectl -n itero run itero-token --rm -i --restart=Never \
  --image=ghcr.io/aegea-dev/itero:0.41.0 \
  --overrides='{"spec":{"securityContext":{"runAsUser":10001,"runAsGroup":10001,"fsGroup":10001},
    "containers":[{"name":"itero-token","image":"ghcr.io/aegea-dev/itero:0.41.0",
    "args":["token","create","laptop"],"stdin":true,
    "volumeMounts":[{"name":"state","mountPath":"/var/lib/itero"}]}],
    "volumes":[{"name":"state","persistentVolumeClaim":{"claimName":"state-itero-0"}}]}}'
kubectl -n itero scale statefulset itero --replicas=1
```

The token reaches only your terminal; `--rm` removes the pod and its
log. The probes, `/livez` and `/readyz`, need no token
([HTTP API](/reference/http/#one-itero-per-machine)).

## Secrets

A container has no OS secret store: a workspace's `$$NAME` reads the
environment, or a folder of secrets the platform mounts, a file each.
Name the folder in `daemon.json`, and mount it:

```json
{ "listen": "0.0.0.0:8443", "secrets": "/run/secrets" }
```

- Compose: give the service `secrets:`; Compose mounts each at
  `/run/secrets/NAME`.
- Kubernetes: mount a Secret as a volume at `/run/secrets`; each key
  becomes a file.

The daemon does not start when the folder named is not there, so add
`secrets` with the mount, not before. A file named `<workspace>.NAME`
is that workspace's own ([On a server](/guides/secrets/#on-a-server)).

## Webhooks

A workspace's [webhook](/guides/webhooks/) connector listens on
127.0.0.1 by default, which nothing outside the container reaches. In a
container, start it with `--host 0.0.0.0`: Compose publishes its port
(add it to `ports`), and on Kubernetes the Service's `webhook` port
reaches it.

## Notifications

A container has no desktop, so a workspace's `#notify` there needs a
channel: list one in `daemon.json` beside `listen`, a webhook's URL as a
secret ([Secrets](#secrets)):

```json
{ "listen": "0.0.0.0:8443",
  "notify": [{ "url": "$$SLACK_WEBHOOK", "format": "slack" }] }
```

Without one, `#notify` fails, saying to add one
([Notifications](/reference/daemon-json/#notifications)).

## Stopping

A stop is SIGTERM: the daemon's connectors get 3 seconds to end, then
the daemon ends. A step cut by the stop runs again when the daemon
starts, as after a crash. Compose's `restart: unless-stopped` and
Kubernetes start it again after a failure.

## Chrome

`#browser` steps run Chrome headless in the Debian image. Chrome needs
more shared memory than Docker's 64 MB: Compose's `shm_size` and the
Kubernetes example's `/dev/shm` volume give it. The image sets
`ITERO_BROWSER_SANDBOX=off` ([The browser](/guides/browser/)).
